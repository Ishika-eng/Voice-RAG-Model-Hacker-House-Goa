How it works

A written walk-through of the pipeline behind every answer — for anyone deciding whether to trust it, not just how to use it.

The pipeline

Every question passes through four checkpoints

None of them are optional, and any of them can end the request early with a plain refusal rather than a guess. This is a harness, not a single prompt-in, text-out call — each stage has typed input/output, retries where a transient failure is plausible (the network calls to Sarvam and Groq), and its own timing measurement.

01
Speech-to-textSarvam's saaras:v3 model transcribes the recorded audio. If it fails or returns nothing, the request ends in a refusal rather than falling through with an empty query.
02
Input guardrailEmpty queries, queries matching unsafe-content patterns, and oversized input are rejected before anything is retrieved.
03
RetrievalThe query is embedded and searched against three separately-indexed chunking strategies in parallel, then merged by Reciprocal Rank Fusion.
04
Topic guardrailIf nothing sufficiently relevant came back, the system refuses instead of answering from weak or unrelated context.
05
GenerationGroq drafts an answer, constrained by a system prompt to use only the retrieved passages — nothing outside that context.
06
Groundedness guardrailThe answer is checked against the retrieved text for actual lexical support. If it doesn't hold up, it's discarded in favor of an honest refusal.

Retrieval

Three chunking strategies, not one

The dataset is indexed three separate ways, each with its own strengths, and a query searches all three at once:

Fixed-size

A 60-word sliding window with 15-word overlap. The dependable baseline when passage structure doesn't help.

Semantic

Sentences are embedded individually and merged while adjacent ones stay topically similar — variable-length, coherent chunks instead of arbitrary cuts.

Passage-native

MS MARCO passages are already curated retrieval units, so this strategy trusts that segmentation instead of re-splitting it.

Results from all three are merged with Reciprocal Rank Fusion — rank-based rather than raw-score-based, since a 60-word window and a single-sentence semantic chunk aren't directly comparable on score alone. Passages MS MARCO's own annotators marked relevant get a small boost in the fusion.

Guardrails

Knowing when not to answer

A model that always answers isn't trustworthy — it's just confident. Three checks stand between a question and an answer:

Input safetyBlocks unsafe or harmful query patterns, empty input, and oversized input before retrieval runs at all.
Off-topic detectionIf the best retrieval match falls below a similarity threshold, the system refuses rather than stretching an answer out of weak context.
GroundednessAfter generation, the answer is checked for how much of it is actually supported by the retrieved text. Below threshold, it's replaced with a refusal — deliberately a fast lexical-overlap check rather than a second LLM call, to stay on the latency-critical path.

Latency

What the 200ms target actually covers

The target applies to the retrieval leg — embedding the query, searching all three collections, and merging results. Chunking happens once, offline, at indexing time, so it's off the query-time path entirely. Generation (the Groq API round-trip) is measured and reported separately and honestly, since no network LLM call finishes in 200ms — folding it into the same number would misrepresent what's actually fast.
